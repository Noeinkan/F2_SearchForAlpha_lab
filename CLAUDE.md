## Non-obvious essentials
- **Dashboard fetch windows end tomorrow** (`full_history_window`): yfinance's `end` is exclusive, so an end of today dropped today's bar. During the session the last bar is today's, still forming. Daily cache files go stale after an hour, not at midnight, and a page opened after the session moved on is sent the current snapshot on load (`_page_load_decision` in `callbacks/data_loading.py`), because the layout is built once at server start
- OHLCV is split- and dividend-adjusted, and corporate-action columns are stripped — [docs/data-adjustment.md](docs/data-adjustment.md). Yahoo is the only wired vendor; the seam for adding another is `_yahoo_history` in `lib/data_processing.py`, and [docs/data-vendors.md](docs/data-vendors.md) records why no free second source exists today
- Transient fetch failures (429/5xx/timeout) are retried then raised as `TransientFetchError` (`lib/fetch_errors.py`); the dashboard renders them as `RATE LIMITED`, distinct from a bad ticker
- **Metrics: `lib/metrics/` is the only implementation of any of them.** `compute_metrics(result_df, capital, interval=...)`. Rates are fractions, ratios annualise at the bar interval, `max_drawdown` is a **positive** magnitude, and `num_trades` is **closed round trips** read from the engine ledger (`result_df.attrs['trades']`) — `num_fills` is the execution count. Percent conversion and `Title_Case_%` UI names live in `lib/metrics/names.py`; never retype a metric name or a `:.2f%`
- **`alpha` is Jensen's alpha, not the difference against buy-and-hold** — that one is `excess_return` (`Excess_Return_%`). The benchmark is the frame's own `Returns` column; the maths is in `lib/metrics/benchmark.py`
- **Deflated Sharpe needs the trial count, which one backtest cannot know.** `compute_metrics` reports a single-trial `deflated_sharpe` equal to `psr`; the combo search re-deflates the whole leaderboard in `apply_deflated_sharpe` (`lib/dash/helpers.py`) once it knows how many combinations ran and how widely they scored. `with_deflated_sharpe` does the same to a `BacktestMetrics`. Formulas in `lib/metrics/deflated.py`
- **Orders: `lib/orders.py` is the only fill model.** `backtest()` defaults to `order_type='market'` — fill at the bar's close — and every pre-3.7 result depends on that, which `test_strategy_snapshot` pins. `limit` / `stop` / `stop_limit` rest in an `OrderBook` and fill against a later bar's High/Low: at the level, or at the **Open** when the bar opened through it. `trailing_stop_orders` and `use_brackets` move the exits into the book and **change results**. When one bar touches several resting orders, `PRIORITY_RULE` decides — open-marketable first, stops before limits, nearest the open — so an ambiguous bracket bar is scored as the stop. Execution-level fills are on `result_df.attrs['fills']`; `attrs['trades']` stays round trips
- **Sessions: `lib/sessions.py` decides where a session starts** — inferred from bar timestamps (every bar on a daily tape; a step > 1.5x the bar spacing on an intraday one), never an exchange calendar. It drives three things: 4h buckets anchored to the session open, `PERIODS_PER_YEAR` = 252 x `BARS_PER_SESSION` (1h emits **7** bars, not 6.5), and `gap_fills` — a stop the market reopened through fills at the **Open**. `Session_Start` on the input frame overrides the inference
- **Panels: `lib/panel.py` aligns many symbols onto one index** — `align_panel({symbol: frame})`, the data layer under the multi-asset engine. The index is the **union** of the members' bars. On a hole the price columns stay **NaN** and `Tradable` is `False`, but `Mark` forward-fills the last close: valuation carries across a hole, execution must not. **Signal columns fill `0`, because a reindexed `_Buy` column holds `NaN` and `NaN` is truthy.** `Session_Start` is inferred once on the merged index and written to every member, so a hole in one symbol is not a session boundary for the basket. Enrich each symbol on its own tape *before* aligning. Semantics: [docs/portfolio-semantics.md](docs/portfolio-semantics.md)
- **Engine: `lib/engine/` is the only bar loop; `backtest()` is a basket of one.** `lib/strategy.py` is now a thin entry point re-exporting the old names; `lib.portfolio.backtest_portfolio(panel, ...)` runs many symbols against **one** `Account`. Each bar is phase-major — every symbol's sells, then every symbol's buys, split by `water_fill` (`lib/engine/allocation.py`) when cash is short. **Fills never write `cash`: they queue on the account, which settles with `math.fsum`, and phase-2 reads use `bar_cash`** — that is what keeps a basket identical under any ticker order. Any engine change must keep `test_strategy_snapshot` and the one-symbol-basket tests in `test_portfolio.py` green. `PortfolioResult`'s shape is provisional (3.8.5–3.8.7); nothing outside tests calls it yet
- **Regime slicing: `lib/regimes/` reads `config/regimes.yaml`, not RESEARCH.md** (agents must not edit that file; `test_repo_calendar_matches_research_md_table` keeps the two in step). Each regime is a separate backtest from flat. A regime without full data is shown but never counted, so the verdict can be `inconclusive` — the normal result on 1h/4h, where Yahoo history misses six of the seven regimes
- Signal columns: `{INDICATOR}_{CONDITION}_Buy` / `_Sell` — see `lib/signals/indicators.py`
- Indicator params: always from `config/strategy_config.yaml` via `lib/config_loader.py`
- Dash callbacks: one file per concern in `lib/dash/callbacks/`; register via `register_*_callbacks(app)` in `callbacks/__init__.py`
- **Quick swap keeps the test window; a plain symbol change resets it.** The swap parks the dates in `test-window-pending-store` with `hold=True`, which `sync_test_window` keeps unclamped. `run_backtest_callback` returns **two** outputs — the results and the `quick-swap-compare-store` row — so every early return needs both. Chain: `callbacks/quick_swap.py`
- Price chart is TradingView Lightweight Charts, **not Plotly**: Python only writes `chart-payload-store` (`lib/dash/chart_payload.py`), the client renders it (`assets/10-sfa-chart.js`). Never add a callback that rebuilds the chart from a pan/zoom event — see [docs/ui-architecture.md](docs/ui-architecture.md)
- Dash dev: `DASH_DEV=1` default; bump `UI_STORAGE_VERSION` in `dash_config.py` when persisted store shape changes
- Dash reload: `DASH_RELOAD=1` opt-in (off by default — Werkzeug reloader is unreliable on Windows; debug error pages still honour `DASH_DEV`)
- **Startup symbol is the last session's, not always TSLA.** `bootstrap.startup_ticker()` reads `state/ui_session.json` and feeds the server bootstrap, the sidebar's initial `ticker-dropdown` and the landing URL `/ticker/<symbol>` — keep those three on one value. The rest of the workspace is restored browser-side through `preset-apply-store`, **without** a ticker so deep links win (`callbacks/ui_session.py`). `SFA_RESTORE_SESSION=0` turns it off; the demo has it off
- Unhandled callback exceptions go to `#error-boundary` via `dash.Dash(on_error=...)` (`lib/dash/error_boundary.py`) and return `no_update` — so a raising callback no longer shows up as a Dash devtools error
- Theme: default is `bloomberg` (dark); header button cycles bloomberg→cvd→light. Palettes in `lib/dash/dash_config.py` `THEMES` (`DEFAULT_THEME`)
- CSS: twelve numbered sheets in `lib/dash/assets/` (`10-tokens.css` … `90-symbol-search.css`), no build step. **Dash injects assets in sorted filename order, so the prefixes are the cascade** — vendored Bootstrap must stay `00-bootstrap.min.css` or every override breaks. File map + editing rules: [docs/ui-architecture.md](docs/ui-architecture.md#stylesheet-layout)
- Flow Scanner: `/flow/<ticker>` reads **one report per ticker** from `state/flow/` (`lib/dash/flow_store.py`), never the root `flow_report.json`; `/flow_report.html?ticker=X` serves the matching HTML. Every write goes through `scan_into_store`, which refuses to replace a good report with a failed scan. `run_dashboard()` rescans stale reports in a background thread (`lib/dash/flow_refresh.py`, `SFA_FLOW_REFRESH_MINUTES`, 0 = off). All Yahoo calls the scanner makes live in `lib/options/chain_source.py`
- **Fundamentals read through a disk cache** (`lib/fundamentals_cache.py`, `state/fundamentals/`): filings 24 h, quote 15 min. `fetch_fundamentals(force=True)` is the Refresh button; `use_cache=False` touches no cache and is what the demo freezer needs, since its price pins would otherwise be skipped by a hit or written into `state/`. A failed or empty refetch never replaces a good entry. SEC code lives in `lib/fundamentals_sec.py`; quarterly Q4 and cash-flow quarters are **derived** from year-to-date totals, and per-share figures are divided by the splits after their **filing date** (split history from Yahoo's price history), so they match split-adjusted prices
- Symbol search: modal at `lib/dash/layout/symbol_search.py` (Ctrl+/). **`ticker-dropdown` is still the current-symbol source of truth for ~15 callbacks** — it is mounted but `display:none` in the sidebar; never delete or re-type it, write to `.value` with `allow_duplicate=True`
- Symbol universe: committed `config/tickers_universe.csv` (~13k rows, sector/industry/asset class), read via `lib/ticker_universe.py`. Regenerate with `python scripts/build_universe.py`; hand-maintained non-equities live in `config/tickers_curated.csv`
- Feedback button: header ✉ → modal (`lib/dash/layout/feedback.py`), delivery in `lib/dash/feedback.py`. Falls back to a pre-filled `mailto:` unless `SFA_FEEDBACK_ENDPOINT` points at a JSON form relay; destination is `FEEDBACK_EMAIL` in `dash_config.py`
- Watchlists: `config/watchlists.json` via `lib/dash/watchlist_storage.py` (disk is source of truth; `watchlists-store` is a mirror). Separate from the flow scanner's `watchlist.txt`
- Outputs: `results/` (parquet), `export/` (Excel)
